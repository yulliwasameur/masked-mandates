## Key findings (written by hand from the run above; not regenerated by the script)

1. **The token format matters a lot against identifier and tool-set linkage.** A stable per-tool pseudonym is
   effectively a principal identifier for a colluding tool coalition: identifier groups merged through co-occurrence
   in clean sessions re-identify 98 % of users at N = 1,000 (F1 0.99) **even with content minimisation**, and still
   65-75 % at N = 10,000. Per-call pseudonyms (Masked Mandates) give a_id = 0 links by construction (that part is
   analytic, as reviewers noted) -- the informative rows are the others.
2. **Timing links calls inside a task.** With E4-calibrated gaps (median 0.38 s, p99 1.55 s) and 1 s timestamps,
   linking calls <= 2 s apart recovers 95 % of same-task pairs at N = 1,000 with 80 % pair precision (73,025 false
   pairs). At N = 10,000, recall stays 97 % but precision drops to 20 % (12.2 M false pairs), because tasks overlap in
   time: only 22 % of calls fall in "clean" segments of <= 6 calls. Larger windows (60 s, 600 s) collapse into
   giant components. The token format does nothing against timing. Only random per-call delays help, at a
   latency cost: U(0, 60 s) delays cut same-task recall at 10 s from 1.00 to 0.56.
3. **Content (call arguments) is the main residual channel for Masked Mandates.** At N = 1,000, with full
   arguments, the combined unsupervised attacker d (sessions + tool set + quasi-identifiers over 30 days)
   re-identifies 23 % of users (3 seeds: 19-30 %; sensitivity-run baseline 12 %). Its pair F1 is 0.40 with 13.8 M
   false pairs. That is in the same range as per-tool-per-day pseudonyms (36 %; seeds 37 +/- 1 %). An attacker
   that knows every user's profile (e_auxmap) re-identifies 81 % (pertool_day: 91 %). Top-1 identification of a
   random call from its reconstructed session is 84 %, versus 47 % from the call alone.
4. **Masked Mandates + content minimisation is where the token format pays off.** Here re-identification drops to
   <= 1 % for every attacker, and top-1 identification is 1-13 % with N = 1,000. The token-level residue (tool,
   time, amount) leaves ~8.3-8.8 bits of entropy out of log2(1000) = 9.97 for the unsupervised attackers. The
   auxiliary-profile attacker still gets 13 % top-1 (7.6 bits). Per-tool pseudonyms with the same minimisation
   remain at 98 % re-identification.
5. **N = 10,000.** Every content-based attack on mm and pertool_day falls to <= 1 % re-identification, even
   e_auxmap. This mostly reflects the attacker's session reconstruction failing under concurrency (1 s
   timestamps, short agent loops). It is **not** a property of the token. An attacker with millisecond
   timestamps, lower load, or smarter de-interleaving would do better. Treat the N = 10,000 MM numbers as
   optimistic for the defender.
6. **Sensitivity (N = 1,000, attacker d, MM with content).** Re-identification rises with fewer favourites (1-3: 40 %)
   and flatter tool popularity (s = 0.5: 18 %). It falls with more favourites (8-15: 8 %), steeper popularity
   (s = 1.5: 1 %), x10 slower loops (0.2 %) and random delays (0 %). It is fairly insensitive to the share of tools
   with personal arguments (8-12 %), because search-topic and tool-set fingerprints carry much of the signal.
   MM + minimisation stays <= 2.4 % in every cell.

## Limitations

- Synthetic population. Quasi-identifier strengths (home city Zipf over 200, presence probabilities) are assumptions
  and move the content rows directly.
- E4 has no per-call turn index. qwen2.5-72b's 4-call / 3-turn rows were split by assuming that identical
  consecutive calls (pay, pay) shared a turn. E4 tools ran locally, so gaps contain no WAN RTT.
- The unsupervised attacker (hard-EM, K = N known, random init) is a heuristic with notable seed variance; a
  stronger one can only do better. e_auxmap is an upper bound that needs per-user background knowledge. Busy
  (non-clean) segments are left as singletons rather than de-interleaved.
- Posterior entropies are calibrated for call_only, a_id and s_session (top-1 ~ p_true). For content-built
  clusters (c, d, e) they are over-confident; read them together with top-1.
- The naive b_time attack on pertool is a giant connected component (pseudonym-timing union chaining). Use c/d
  for that baseline.
- One population draw per cell, except 3 replicate seeds for the N = 1,000 baseline of attacker d. Posterior uses
  400 targets and caps evidence at 200 calls per cluster.
