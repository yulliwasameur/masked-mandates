# E3 v2.2 -- collusion / linkage study (summary)

Generated by `sim/e3v22.py aggregate` from 625 cells (5 world seeds [20261109, 20261210, 20261311, 20261412, 20261513], identical in every setting). Full data incl. every per-seed cell: `results/e3v22.json`. Figures: `results/e3v22_main.png`, `results/e3v22_coalition.png`, `results/e3v22_sensitivity.png`, `results/fig_e3_load.pdf`. Changes w.r.t. v2.1 (results/e3v21.json, kept): gap calibration from the E4 v2.1 Masked-Mandates runs, delegations and an issuer-in-the-coalition attacker, a load / concurrency sweep, seed ranges for every reported number; attackers and metrics are unchanged.

Cells are reported as **mean [min-max over the 5 seeds]**; the bootstrap 95 % CI of the mean over seeds is in the JSON and in the sensitivity table (with 5 draws it is descriptive, not a guarantee).

## Definitions

* **Profile recovery** (was "re-identification" in v2): for a user with >= 10 calls visible to the coalition, take the attacker cluster that holds the largest number of the user's calls; the profile is recovered if that cluster holds >= 50 % of the user's visible calls AND >= 80 % of the cluster's calls belong to the user. Rate = recovered users / users with >= 10 visible calls. It measures linkage of a user's activity into one pure profile, not naming (naming = identified-tool attacker).
* **Attackers** (all tools of the coalition pool their logs): a_id identifier equality; b_timeD naive single-linkage of calls <= D ms apart unioned with identifiers; b_trackT / b_trackA ms multi-session tracker (timing [+ counter j], / + exact-amount matches) unioned with identifiers; s_atoms = stage-1 atoms (tracker-A sessions + identifier groups merged by co-occurrence); c_sessQI / d_full = 30-day hard-EM clustering of the atoms on quasi-identifiers + hour (c) and + tool set (d, combined attacker); e_oracle = **profile-oracle attacker** (atoms assigned to the max-likelihood user under the TRUE profiles; not an upper bound); id_* = identified-tool attacker (names from identifying calls; sess / clu / cls stages, see docstring).
* **Per-call top-1**: profile-oracle posterior (v2 code) puts the highest mass on the true user, from the call alone, from its reconstructed session (tracker A), from its stage-1 atom, from its a_id group and from its d_full cluster.
